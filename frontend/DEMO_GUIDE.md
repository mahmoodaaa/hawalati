# حوالتي — دليل تجربة الفرونت المتصل بالباك

كل العمليات Demo فقط: لا تحويلات بنكية حقيقية، ولا SMS حقيقي، ولا مطابقة وجه حقيقية.

## التشغيل

شغّل الباك من IntelliJ على `http://localhost:7171` مع PostgreSQL وإعداداتك المحلية. الحوالات التجريبية تُزرع عند تشغيل الباك بملف `demo`.

من مجلد frontend:

```powershell
npm.cmd ci
npm.cmd run dev
```

افتح `http://localhost:5173`. عنوان الباك في `.env` هو `VITE_API_BASE_URL=http://localhost:7171`.

## تجهيز مستخدم الاستلام

سورس `DemoRemittanceInitializer` يربط جميع الحوالات المزروعة بالرقم الوطني **التجريبي** `9912345678`. يجب أن يكون حساب الاستلام بنفس الرقم، مفعّلًا، وKYC فيه VERIFIED أو DEMO_VERIFIED.

إذا كان هناك حساب مسجل بهذا الرقم، استخدم حسابه الموجود. لا تسجل حسابًا ثانيًا بنفس الرقم ولا تغيّر الرقم الوطني للحساب. إن لم يوجد، يمكن تسجيل حساب تجريبي بهذا الرقم عبر المسار الجديد، باستخدام هاتف غير مسجل ووثيقة اختبار لا تحتوي معلومات شخصية حقيقية.

حساب جديد برقم وطني مختلف يمكنه اختبار التسجيل والبروفايل والوثيقة، لكنه لن يجد الحوالات المزروعة لهذا المستفيد. ظهور NOT_FOUND في هذه الحالة سلوك صحيح. لتجربة استلام تخص مستخدمًا آخر، يحتاج المسؤول تجهيز حوالة Demo مطابقة له؛ لم نعدّل بيانات قاعدة البيانات أو الـ seed في هذا الربط.

## رحلة الاستلام

1. سجّل الدخول بالحساب المطابق للمستفيد ثم OTP LOGIN.
2. من Home اضغط استلام حوالة، اختر مصدرًا محليًا/دوليًا ثم الجهة.
3. أدخل المرجع والمبلغ التقريبي **بالدينار الأردني JOD** مهما كانت العملة الأصلية. API البحث يرسل `{referenceNumber,providerId,approxAmount}`.
4. AVAILABLE يعرض الحوالة الحقيقية وUUID من الباك. NOT_FOUND وPROVIDER_MISMATCH وALREADY_RECEIVED لها شاشات منفصلة؛ لا يوجد fallback للـ mock.
5. اختر Bank أو Wallet وأدخل التفاصيل.
6. راجع الحوالة والوجهة. رسوم 1.50 JOD والصافي على المراجعة تقدير Demo فقط؛ الإيصال والسجل يعرضان القيم الفعلية من السيرفر.
7. فعّل مربع الموافقة، ثم اضغط التأكيد مرة واحدة. لا يُرسل Receive قبل الخطوتين. الطلب يحمل `remittance.id` كـ remittanceId، وdestination/details، وagreed=true.
8. Success يعرض رقم العملية ووقتها وحالتها ورسومها وصافيها والوجهة المقنّعة من الباك. عند فقد نتيجة Success افتح سجل العمليات؛ لا يُختلق إيصال محلي.
9. افتح History من الزر العلوي أو التنقل السفلي. أعد تحميل الصفحة للتأكد أن العمليات تُسترجع من الباك. Home يعرض آخر ثلاث عمليات من نفس API.

## الحالات السلبية

- مرجع غير موجود أو مستفيد مختلف أو مبلغ بعيد عن المطلوب → NOT_FOUND. في الباك السماحية أكبر القيمتين: 2 JOD أو 10% من المبلغ المتوقع.
- مرجع للمستفيد الصحيح مع جهة أخرى → PROVIDER_MISMATCH، باستخدام expectedProvider من الباك.
- مرجع مستلم → ALREADY_RECEIVED، ومحاولة تأكيد نسخة قديمة من نتيجته → HTTP 409 واضح بدون نجاح وهمي.
- KYC غير مكتمل → واجهة الاستلام توجّه إلى KYC، والباك يرفض lookup/receive أيضًا.
- انقطاع الشبكة أثناء Receive → راجع السجل قبل إعادة المحاولة؛ قد يكون الطلب اكتمل على السيرفر رغم ضياع الرد.
- صلاحية Access Token المنتهية → apiRequest يستخدم آلية refresh الموجودة؛ فشل التجديد يعيد المستخدم لتسجيل الدخول.

## الملف الشخصي والوثيقة

افتح Profile من الأعلى/الأسفل. يتم GET للبروفايل عند الفتح، وPUT للحقول المسموحة فقط عند الحفظ. الرقم الوطني وكلمة المرور لا يُرسلان ضمن حفظ الملف. تغييرات الهوية قد تعيد KYC إلى PENDING حسب نتيجة الباك.

زر عرض الوثيقة أو استبدالها يفتح KYC: metadata عبر GET /api/user/document، والاستبدال عبر PUT FormData بملفي file وdocumentType دون ضبط Content-Type يدويًا. يُحدّث البروفايل بعد الرفع، ثم بعد نجاح POST /api/user/kyc. اختيار ملف أو رفعه لا يكفي لإظهار DEMO_VERIFIED.

التسجيل الجديد يظل معلومات → هاتف → وثيقة → مراجعة KYC → Phone OTP → إنشاء بيانات دخول → registration/complete → Home. الوثيقة الأولية تُحفظ مرة واحدة ضمن التسجيل النهائي، ولا يعاد رفعها عبر API الوثيقة.

## Reset والاختبارات

أُزيل زر Reset Demo؛ تنظيف المتصفح لا يعكس استلام الحوالات في PostgreSQL. استخدم مرجعًا غير مستلم، أو اطلب من المسؤول تجهيز بيانات Demo مناسبة خارج الواجهة.

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run lint
```

37 اختبارًا آليًا ناجحًا. هذه الاختبارات تستخدم HTTP mocked للتحقق من العقود، وتشمل Lookup، Bank/Wallet Receive، UUID والموافقة، الرسوم من السيرفر، 409، History، JWT refresh، تحديث Profile، الوثيقة والتسجيل. لا تثبت هذه الاختبارات وحدها قبول المتصفح.

لم نعدّل الباك أو بياناته ضمن هذا العمل. تبقى التجربة اليدوية الكاملة للحوالات والبروفايل والوثيقة في المتصفح مطلوبة قبل اعتماد العرض النهائي.
